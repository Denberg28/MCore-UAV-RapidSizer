# MCore Rapid Prototype Development Gates

This gate model is intended to prevent the rapid-prototyping workflow from skipping essential engineering evidence.

## Gate 0 — Mission definition

Required:
- mission and operating environment
- design mass target
- stall/cruise/endurance/climb targets
- payload definition
- regulatory operating concept

Output: traceable requirements.

## Gate 1 — Concept sizing

Required:
- wing sizing
- wing loading/aspect ratio
- power and energy budget
- thrust target
- preliminary packaging

Output: MCore rapid-sizing report.

## Gate 2 — Mass and CG closure

Required:
- component mass inventory
- datum definition
- measured mass replacing estimates where practical
- CG within project-derived permissible range
- assembly mass reconciliation

Output: controlled weight-and-balance record.

## Gate 3 — Propulsion bench validation

Required:
- exact motor/propeller/ESC/battery combination
- measured static thrust
- voltage/current/RPM
- temperature
- battery voltage sag
- continuous and peak operating limits

Output: validated propulsion data map.

## Gate 4 — Aerodynamic / stability / controls

Required as applicable:
- aerodynamic model or validated empirical data
- static margin / neutral point
- control surface sizing and control authority
- trim cases
- actuator torque/load margins

Output: stability-and-control evidence.

## Gate 5 — Structure and integration

Required as applicable:
- design load cases and factors
- spar/fuselage/attachment load paths
- stress, buckling, deflection
- vibration and propulsion mount review
- wiring/power distribution protection
- fail-safe/failure-mode review

Output: structural/integration substantiation.

## Gate 6 — Ground test

Required:
- configuration freeze/version
- control-direction check
- failsafe behavior
- range/link check
- propulsion run
- taxi/launch/recovery system check as applicable
- documented discrepancies

Output: ground-test release record.

## Gate 7 — Incremental flight test

Required:
- defined test cards
- constrained envelope expansion
- telemetry/logging
- abort criteria
- discrepancy and configuration tracking

Output: flight-test evidence and updated model assumptions.

## Gate 8 — Design iteration

Replace estimates with evidence, update the MCore project, regenerate the report, and repeat the relevant gates.
